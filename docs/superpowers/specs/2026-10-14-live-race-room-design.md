# Live Race Room — Design

- วันที่: 2026-10-14
- สถานะ: รอรีวิว
- ขอบเขต: โหมดแข่งสดแบบห้อง (คล้าย Kahoot) สำหรับบูธในงาน event ของ Debug Master

## 1. เป้าหมายและผู้ใช้

ที่บูธมีผู้เล่นกลุ่มละ 4–10 คนเวียนกันมาแข่งเป็นรอบ ๆ สตาฟฟ์เลือกโหมดและเวลา แล้วกดเริ่ม ทุกคนเล่นพร้อมกัน
ส่วนจอใหญ่โชว์ตัวละครวิ่งแข่งกันตามคะแนนแบบ realtime เพื่อดึงคนที่เดินผ่าน

**ความสำเร็จ**
- คนดูมองจอใหญ่แล้วรู้ทันทีว่าใครนำ
- เวลาทุกจอเดินตรงกัน (คลาดไม่เกินประมาณ 0.5 วินาที)
- สตาฟฟ์เปิดรอบใหม่ได้ภายในไม่กี่วินาที
- เน็ตหลุดชั่วคราวแล้วไม่ทำให้รอบพัง

**สิ่งที่ตกลงกันแล้ว**

| เรื่อง | ข้อสรุป |
|---|---|
| ที่ใช้ | บูธ event ผู้เล่นกลุ่มเล็ก แข่งกันเป็นรอบ |
| อุปกรณ์ | เครื่องของบูธ + มือถือผู้เล่นที่สแกน QR เข้ามา (จึงต้องมีเซิร์ฟเวอร์ที่เข้าผ่านอินเทอร์เน็ตได้) |
| กติกา | แข่งตามเวลา คะแนนสูงสุดตอนหมดเวลาชนะ ใช้สูตรคะแนนเดิม (speed × combo) |
| เวลาต่อรอบ | สตาฟฟ์เลือก 8 / 10 / 15 นาที หรือกำหนดเอง 1–15 นาที ค่าเริ่มต้น 8 |
| ด่าน | สตาฟฟ์เลือกโหมด A/B/C ต่อรอบ ทุกคนเล่นด่านชุดเดียวกันตามลำดับเดียวกัน |
| การควบคุม | หน้าคุม (Host) แยกบนมือถือหรือแท็บเล็ตของสตาฟฟ์ จอใหญ่แสดงผลอย่างเดียว |
| ลู่วิ่ง | คนละเลน เลนไม่สลับตลอดรอบ ตำแหน่ง = คะแนนสะสม และมีตารางอันดับสดด้านขวา |
| คนที่มาระหว่างรอบ | เข้าห้องไม่ได้ ต้องต่อคิวรอบหน้า |
| จำนวนคน | สูงสุด 12 คนต่อรอบ |
| ธีม | ใช้ธีมของเกมเดิมทั้งหมด (ดูข้อ 5) |
| Backend | Cloudflare Worker + Durable Object (ดัดแปลงจาก `RaceRoom` ของ Signal Lost) |

**ไม่ทำในเวอร์ชันนี้:** ประวัติการแข่งข้ามวัน, หลายห้องบนจอเดียว, ระบบกันโกงจริงจัง, โหมดออฟไลน์ตอนเน็ตบูธล่มทั้งหมด, การบันทึกผล Live ลง Ranking ในเครื่อง

## 2. สถาปัตยกรรม

```
game/ (Nuxt static บน GitHub Pages เหมือนเดิม)       live-server/ (ใหม่: Cloudflare Worker)
├─ เกมเดิม + โหมด Live (?room=CODE)  ─┐                └─ LiveRoom: Durable Object 1 ตัวต่อห้อง
├─ /live/host    หน้าคุมของสตาฟฟ์     ─┼── WebSocket ──►     (idFromName(code), hibernatable WS,
└─ /live/screen  จอใหญ่                ─┘                       state + alarm ใน DO storage)
      wss://<live-server>/rooms/:code/ws?role=player|host|screen
```

- `live-server/` เป็นโฟลเดอร์ใหม่ใน repo นี้ มี `package.json`, `wrangler.jsonc` และ vitest ของตัวเอง deploy ด้วย `wrangler` แยกจาก GitHub Pages
- ตัวเกมอ่าน URL ของ worker จาก `runtimeConfig.public.liveUrl` (env `NUXT_PUBLIC_LIVE_URL`) ถ้าไม่ได้ตั้งค่า เมนู Live จะไม่แสดง และเกมทำงานเหมือนเดิมทุกอย่าง
- **ห้องเป็นของบูธ ไม่ใช่ของรอบ:** ห้องเดียว (เช่น `CODI-1`) ใช้ได้ทั้งวัน แต่ละรอบคือการรีเซ็ตห้องนั้น (`roundId` +1)
- QR บนจอใหญ่ชี้ไปที่ `<origin>/debug-master/?room=CODI-1` โดยใช้ `app.baseURL` ของ Nuxt ต่อ path ไม่ฮาร์ดโค้ด

## 3. Flow ของรอบ

1. **Lobby:** ผู้เล่นสแกน QR หรือเปิดเกมบนเครื่องบูธด้วย `?room=` แล้วตั้งชื่อ/อายุ/ตัวละครด้วย `PlayerSetupDialog` เดิม จากนั้นเข้าห้อง
   - ตัวละครไปยืนรอที่เส้นสตาร์ทบนจอใหญ่
   - สตาฟฟ์เลือกโหมดกับเวลาบนหน้าคุม
2. **Start:** เซิร์ฟเวอร์ตั้ง `phase = 'countdown'`, `startAt = now + 3000`, `endAt = startAt + durationSec * 1000` แล้วตั้ง alarm ที่ `startAt`
   - ทุกจอนับ 3-2-1 ตามนาฬิกาที่ปรับแล้ว
3. **Running:** alarm เปลี่ยน `phase = 'running'` แล้วตั้ง alarm ใหม่ที่ `endAt`
   - ผู้เล่นเล่นด่านของโหมดตามลำดับ และส่ง `progress` (ข้อ 4)
   - เซิร์ฟเวอร์จัดอันดับแล้ว broadcast
4. **หมดเวลา:** alarm ที่ `endAt` เปลี่ยน `phase = 'finished'` (หรือสตาฟฟ์กด `endEarly`)
   - client ล็อกปุ่มทันทีที่นาฬิกาที่ปรับแล้วถึง `endAt` โดยไม่รอเซิร์ฟเวอร์
   - เซิร์ฟเวอร์ยังรับ `progress` ที่มาช้ากว่า `endAt` ได้ไม่เกิน 2,000 ms แล้วค่อยปิดผลสุดท้าย
5. **ผลรอบ:** จอใหญ่โชว์โพเดียมกับรายชื่อที่เหลือ ผู้เล่นเห็นอันดับของตัวเอง ผลค้างไว้จนสตาฟฟ์เปิดรอบใหม่
6. **รอบใหม่ (`newRound`):** ห้องกลับเป็น `lobby` และ `roundId` +1
   - ผู้เล่นที่ยังเชื่อมต่ออยู่อยู่ต่อ (คะแนนรีเซ็ต) ส่วนคนที่หลุดถูกล้างออก
   - คนในคิวเข้าเป็นผู้เล่นตามลำดับที่ต่อคิว จนครบ 12 คน
   - เลนจัดใหม่ตามลำดับ: คนที่อยู่ต่อก่อน แล้วตามด้วยคิว

### คิวรอบหน้า
- ถ้า `hello` มาตอน `countdown`/`running`/`finished` จะได้สถานะ `queued` ไม่ได้เลน และไม่ได้เล่นรอบนี้
- มือถือของคนในคิวขึ้น "คุณอยู่ในคิวรอบหน้า" พร้อมเวลาที่เหลือของรอบปัจจุบัน และโชว์ลู่วิ่งของรอบนี้ให้ดู
- **เพดาน 12 คน:** นับรวม (ผู้เล่นที่ยังเชื่อมต่อ + คิว) ถ้าครบแล้วจะได้ `{type:'full'}` และหน้าจอขึ้น "ห้องเต็ม"
- ผู้เล่นกด "ออกจากห้อง" (`leave`) ได้ เครื่องบูธใช้ "เปลี่ยนผู้เล่น" ซึ่งคือ `leave` แล้วตามด้วยตั้งค่าผู้เล่นใหม่และ `hello` ด้วย `pid` ใหม่
- ตอน `lobby` ถ้ายังไม่ครบ 12 คน `hello` จะได้เป็นผู้เล่นทันที

## 4. ข้อมูลและข้อความ

### สถานะห้อง (เซิร์ฟเวอร์ถือคนเดียว เก็บใน DO storage key `room`)

```ts
type Phase = 'lobby' | 'countdown' | 'running' | 'finished'
type ModeId = 'A' | 'B' | 'C'

interface LivePlayer {
  id: string            // pid คงที่ต่อเครื่อง (localStorage 'debug-master:live-pid')
  name: string          // ≤ 24 UTF-16 units ตาม homeConfig.nicknameMaxLength
  avatarId: string      // ต้องเป็น PlayerAvatarId ที่มีอยู่ ไม่งั้นใช้ตัว default
  age: number           // 5–18
  status: 'playing' | 'queued'
  lane: number | null   // 0..11 ล็อกตลอดรอบ, null เมื่อ queued
  score: number
  levelsCompleted: number
  bestCombo: number
  combo: number         // combo ปัจจุบัน ใช้โชว์ 🔥 บนจอใหญ่
  connected: boolean
  joinedAt: number
  queuedAt: number | null
}

interface RoomState {
  code: string
  phase: Phase
  mode: ModeId
  durationSec: number   // 60..900, ค่าเริ่มต้น 480
  roundId: number
  startAt: number | null
  endAt: number | null
  serverNow: number     // epoch ms ตอนส่ง ใช้ปรับนาฬิกา
  players: LivePlayer[] // playing ก่อน queued; ใน playing เรียง score DESC → levelsCompleted DESC → joinedAt ASC; queued เรียง queuedAt ASC
  screens: number
  hosts: number
}
```

- ด่านไม่ส่งผ่านเน็ต: client ใช้ `homeConfig.modes[mode]` (levelSetId + levelRange) ที่มีในเกมอยู่แล้ว ทุกเครื่องจึงได้ด่านชุดเดียวกันตามลำดับเดียวกัน
- เซิร์ฟเวอร์ไม่ต้องรู้จักรายละเอียดด่าน รู้แค่ว่า mode เป็น `'A' | 'B' | 'C'`

### ข้อความ

| ทิศทาง | ข้อความ |
|---|---|
| player → server | `{type:'hello', pid, name, avatarId, age}` |
| | `{type:'progress', roundId, score, levelsCompleted, bestCombo, combo}` ส่งเป็นค่าสะสม ตอนผ่านด่านและตอน combo เปลี่ยน client จำกัดไม่เกิน 4 ครั้งต่อวินาที และส่งค่าล่าสุดเสมอ |
| | `{type:'leave'}` |
| host → server (ต้องเชื่อมต่อด้วย host key) | `{type:'setMode', mode}` · `{type:'setDuration', durationSec}` (ทั้งสองอันใช้ได้เฉพาะ `lobby`) |
| | `{type:'start'}` (ต้องมีผู้เล่นอย่างน้อย 1 คน) · `{type:'endEarly'}` · `{type:'newRound'}` · `{type:'kick', playerId}` |
| screen → server | `{type:'hello'}` |
| server → ทุกคน | `{type:'state', state: RoomState}` ส่งทุกครั้งที่สถานะเปลี่ยน จำกัดไม่เกิน 10 ครั้งต่อวินาที (ส่งค่าล่าสุดตามหลัง) |
| server → คนเดียว | `{type:'you', pid, status}` · `{type:'host', host}` (ตอบ host `hello`) · `{type:'full'}` · `{type:'kicked'}` · `{type:'error', error:'not_host' \| 'bad_message'}` |

### การตรวจข้อความใน `room-logic`
- ข้อความยาวไม่เกิน 2 KB ต้องเป็น JSON และ `type` ต้องรู้จัก ไม่งั้นทิ้งเงียบ ๆ
- `progress` รับเฉพาะเมื่อ:
  - `phase === 'running'` (หรืออยู่ภายใน 2,000 ms หลัง `endAt`)
  - `roundId` ตรงกับรอบปัจจุบัน และผู้ส่งมี `status === 'playing'`
- **ห้ามลด:** `score` และ `levelsCompleted` ต้องไม่น้อยกว่าค่าเดิม ถ้าน้อยกว่าให้ทิ้ง เพื่อให้ข้อความซ้ำหรือมาช้าไม่ทำอะไร
- **เพดาน:** คะแนนเพิ่มได้เฉพาะตอนผ่านด่าน จึงต้องเป็น `Δscore ≤ ΔlevelsCompleted × maxLevelPoints(bestCombo)`
  - `maxLevelPoints` คือสูตร `calculateLevelScore` ใน `index.vue` ในกรณีที่แย่ที่สุด (id ด่าน 50, จำนวนก้าวมากสุดของชุด A/B/C, speed 4.5, combo = `bestCombo`)
  - เพดานนี้ใช้กันค่าผิดปกติ ไม่ใช่ระบบกันโกง
- ชื่อตัดอักขระควบคุมออก, ตัดช่องว่างหัวท้าย, จำกัด 24 UTF-16 units โดยไม่ตัดกลาง emoji
- ข้อความ host จากการเชื่อมต่อที่ไม่ใช่ host ได้ `error: not_host` และไม่มีผลกับห้อง

### Host key
- หน้า `/live/host` ถ้ายังไม่มี key จะมีปุ่ม "สร้างห้อง" ให้กรอกรหัสห้องที่ต้องการ (`^[A-Z0-9-]{3,16}$`)
  - หน้าเว็บสุ่ม host key 32 ตัวอักษรเก็บใน localStorage แล้วต่อด้วย `role=host&key=…`
- เซิร์ฟเวอร์เก็บแค่ SHA-256 ของ key: host คนแรกจองห้อง คนต่อไปต้องมี key เดียวกัน (กลไกเดียวกับ ADR 0015 ของ Signal Lost)
- หน้าคุมมีปุ่ม "คัดลอกลิงก์หน้าคุม" (ลิงก์มี key) ไว้ให้สตาฟฟ์อีกเครื่องใช้
- จอใหญ่ (`role=screen`) ไม่ต้องใช้ key และคุมห้องไม่ได้

### 5.1 จอใหญ่: ระหว่างแข่ง (`RaceLanes` + `LiveBoard`)
- **HUD ด้านบน:**
  - ป้าย `LIVE RACE · CODI-1`
  - กล่อง metric โหมด, เวลาที่เหลือ, จำนวนผู้เล่น
  - 30 วินาทีสุดท้ายกล่องเวลาเป็น `time-low` (กะพริบแดงทุกวินาที) แบบเดียวกับเกม

  - `trackMax = niceCeil(max(TRACK_BASELINE, leaderScore / 0.85))` และ `x = score / trackMax`
  - `niceCeil` ปัดขึ้นเป็นขั้น 1,000/2,000/5,000
  - ขีดบอกคะแนนด้านบนเปลี่ยนตาม `trackMax` เมื่อ `trackMax` เพิ่ม ลู่จะขยายแบบนุ่มนวล (ทุกตัวขยับซ้ายพร้อมกัน 600 ms)
  - `TRACK_BASELINE` เป็นค่าคงที่ใน `track.ts` เริ่มที่ 5,000 ทุกโหมด แล้วปรับตัวเลขตอนซ้อม
- **ตัวละคร:**
  - avatar วิ่ง (hop) ประมาณ 1.2 วินาทีหลังคะแนนเพิ่ม แล้วยืนนิ่ง ตำแหน่งเลื่อนแบบ ease-out
  - ป้ายชื่อ glass แสดงชื่อกับคะแนนเหลือง
  - คนนำมีขอบทองกับมงกุฎ (svg เดียวกับ Ranking)
  - `combo ≥ 5` มีป้ายส้ม `×N` แบบ combo-hot
- **ตารางอันดับสด (ขวา):** แถวแสดงอันดับ, avatar, ชื่อ, คะแนน อันดับ 1–3 ใช้สีเหรียญ
  - เมื่ออันดับเปลี่ยน แถวสลับที่แบบ FLIP 300 ms ส่วนเลนบนลู่ไม่สลับ
- **`QueueStrip`:** มุมล่าง "คิวรอบหน้า" แสดง avatar ของคนในคิว ซ่อนเมื่อคิวว่าง

### 5.2 จอใหญ่: Lobby (`LobbyStage`)
- QR บนการ์ดสีขาวมุม `--cv-radius-xl` และรหัสห้องตัวใหญ่สีเหลือง
- ป้าย "รอบถัดไป · โหมด X · N นาที" และ Codi ท่าชนะ (`PLAYER_POSES.win` · `codi-win.svg`) ทักทาย
- ช่องผู้เล่น 12 ช่องบนกระเบื้อง grass ช่องที่ยังว่างเป็นเส้นประ คนเข้าใหม่เด้งลงช่อง
- สร้าง QR ในเครื่อง ไม่เรียกบริการภายนอก ใช้ `uqr` (unjs ไม่มี dependency สร้าง SVG ได้)

### 5.3 จอใหญ่: ผลรอบ
- หัวข้อ "จบรอบ! ผู้ชนะ" ตามด้วยโพเดียม 1–3 ที่ขึ้นตามลำดับ 3 → 2 → 1 แล้วมงกุฎเด้งขึ้น และอันดับ 4 ลงไปเป็นแถวด้านล่าง
- เสียงจบรอบใช้ cue completion เดิมของ `useGameAudio`

### 5.4 หน้าคุม (`/live/host`)
- พื้นหลังอวกาศ บนการ์ดสีขาวแบบ `PlayerSetupDialog` ปุ่มทุกปุ่มสูงอย่างน้อย 48 px
- **Lobby:**
  - เลือกโหมด A/B/C (radio การ์ด)
  - เลือกเวลา 8/10/15/กำหนดเอง (1–15 นาที)
  - รายชื่อผู้เล่นและคิว มีปุ่มเตะ คนที่หลุดแสดงเป็นสีเทา
  - ปุ่ม `--cv-cta` "▶ เริ่มแข่ง N นาที" (กดไม่ได้ถ้ายังไม่มีผู้เล่น)
- **Running:** เวลาที่เหลือ, อันดับย่อ, ปุ่ม "จบรอบก่อนเวลา" (ต้องยืนยันใน dialog ที่ focus ปุ่มยกเลิก)
- **Finished:** ปุ่ม "เปิดรอบใหม่"
- แสดงสถานะการเชื่อมต่อ ปุ่มคุมทั้งหมดกดไม่ได้ระหว่างเน็ตหลุด

### 5.5 ผู้เล่น (หน้าเกมเดิมในโหมด Live)
- เปิดด้วย `?room=CODE` แล้วตั้งค่าผู้เล่นด้วย `PlayerSetupDialog` (ข้ามการเลือกโหมด เพราะสตาฟฟ์เลือกให้) จากนั้นเข้าหน้ารอ "รอสตาฟฟ์กดเริ่ม" ที่มีชื่อ, avatar, โหมดกับเวลาของรอบ
- พอสตาฟฟ์กดเริ่ม: นับ 3-2-1 แล้วเข้าเกม ใช้กระดาน/โค้ด/D-pad/คะแนน/combo เดิมทั้งหมด
  - HUD ใช้เวลาจาก `endAt` ที่ปรับแล้ว และเพิ่มช่อง "อันดับ N/M"
- **หมดเวลา:** ล็อก input แล้วส่ง progress สุดท้าย หน้าผลแสดงอันดับกับคะแนนของตัวเอง
  - ไม่บันทึกลง `ScoreRepository` และไม่ใช้ idle timeout 90 วินาทีระหว่างอยู่ในห้อง
- **คิว / ห้องเต็ม / ถูกเตะ:** มีหน้าบอกสถานะชัดเจน ถูกเตะแล้วกลับหน้าแรก
- เครื่องบูธมีปุ่ม "เปลี่ยนผู้เล่น" ในหน้ารอและหน้าผล

## 6. เน็ตหลุดและกรณีพิเศษ

| เหตุการณ์ | สิ่งที่เกิดขึ้น |
|---|---|
| ผู้เล่นหลุดกลางรอบ | เล่นต่อในเครื่องได้ นาฬิกาอิง `endAt` ที่มีอยู่แล้ว ต่อใหม่ด้วยระยะรอ 0.5 → 1 → 2 → 4 → สูงสุด 8 วินาที (สุ่มคลาดเล็กน้อย) พอต่อได้ก็ส่ง `hello` แล้ว `progress` ล่าสุดทันที |
| ต่อกลับด้วย `pid` เดิม | ได้สถานะ, เลน และคะแนนเดิมคืน (เอาค่าที่มากกว่าระหว่างเซิร์ฟเวอร์กับ client) |
| ต่อกลับหลัง `endAt` + 2 วิ | คะแนนที่ทำได้ตอนหลุดจะไม่ถูกนับ ใช้ค่าล่าสุดที่เซิร์ฟเวอร์ได้รับ หน้าผลแจ้งว่า "บันทึกคะแนนล่าสุดที่ส่งทันเวลา" |
| หน้าคุมหรือจอใหญ่หลุด | รอบเดินต่อ alarm ปิดรอบเอง ต่อใหม่แล้วได้ `state` ล่าสุดทั้งห้อง |
| deploy / DO restart | state กับ alarm อยู่ใน storage ทุกจอต่อกลับเองด้วย backoff เดียวกัน |
| `start` ซ้ำหรือ `newRound` ระหว่างแข่ง | `start` ใช้ได้เฉพาะ `lobby` ส่วน `newRound` ใช้ได้เฉพาะ `finished` (ต้องกด `endEarly` ก่อน) |
| ห้องถูกทิ้ง | alarm ลบ storage หลังไม่มีใครใช้ 6 ชั่วโมง |
| เน็ตบูธล่มทั้งหมด | เล่นต่อในเครื่องได้ แต่จอใหญ่ไม่อัปเดต (ไม่อยู่ในขอบเขตเวอร์ชันนี้) |

## 7. การทดสอบ

- **`live-server/` (vitest):** ทดสอบ `room-logic.ts` ครบ:
  - การเปลี่ยน phase และ phase ที่ห้ามเปลี่ยน
  - countdown, ปิดรอบตาม `endAt`, ช่วงผ่อนผัน 2 วินาที
  - การตรวจ progress (ห้ามลด, เพดาน, `roundId` ผิด, ส่งโดยคนในคิว)
  - คิวกับเพดาน 12 คน, `newRound` ย้ายคิวเข้าเล่น, `leave`/`kick`
  - การต่อกลับด้วย `pid` เดิม, สิทธิ์ host, การจัดเรียงอันดับ
- **`game/` (เพิ่ม vitest เฉพาะฟังก์ชันล้วนตัวใหม่):** `clock.ts` (ปรับนาฬิกา, เวลาที่เหลือ) และ `track.ts` (`trackMax`, `niceCeil`, ตำแหน่ง)
  - UI ตรวจด้วย `pnpm build` ตามแนวทางเดิมของโปรเจกต์
- **ซ้อมก่อนงาน (manual checklist):** รัน `wrangler dev` เปิดจอใหญ่ หน้าคุม และผู้เล่นอีก 3 จอ (มีมือถือจริงอย่างน้อย 1 เครื่อง)
  1. เข้าห้อง แล้วเลือกโหมดกับเวลา (ใช้ "กำหนดเอง 1 นาที" เพื่อซ้อมเร็ว)
  2. เริ่ม แล้วดูว่า countdown ตรงกันทุกจอ
  3. ปิดเน็ตผู้เล่น 1 เครื่อง 10 วินาที แล้วต่อกลับ ดูว่าคะแนนตามทัน
  4. รีโหลดจอใหญ่ระหว่างแข่ง
  5. สแกนเข้าระหว่างแข่ง แล้วดูว่าขึ้นคิว
  6. ปล่อยให้หมดเวลา ดูว่าผลตรงกันทุกจอ
  7. เปิดรอบใหม่ ดูว่าคิวเข้ามาเล่นได้
  8. ลองเข้าคนที่ 13 แล้วดูว่าขึ้นห้องเต็ม
